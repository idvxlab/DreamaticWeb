# Dreamatic · Web

基于 **Pi Harness 1.3.0** 的本地三智能体网页创作系统。从用户需求、文档、表格、图片和公开网站提取内容，生成响应式 HTML，并通过可视化画布继续修改。

沿用 Dreamatic 的深色侧栏、暖灰背景、橙色和浅绿色视觉语言。从本地 `DreamaticWebV1.zip` 恢复可复用基础代码后完善，不修改 Dreamatic，也不复制 Pi 内部代码。UI 规范与可访问性/编辑式设计知识复用自相邻 Dreamatic。开发前检查与实施记录见 [实施计划](docs/implementation-plan.md)。

## 启动

需要 Node.js 22.19+。

```sh
npm ci --ignore-scripts
cp .env.example .env
# 可在 .env 配置，或启动后在“模型与设置”下拉选择供应商、模型和运行模式
npm run dev
```

打开 http://127.0.0.1:5173 。API 默认监听 http://127.0.0.1:4310 。

未配置密钥也可体验完整上传、演示生成、编辑和导出流程：

```sh
DREAMATIC_MODE=demo npm run dev
```

演示模式会在界面、运行记录和输出中标明，不进行 AI 语义分析。在左上角 Dreamatic 品牌菜单中打开“模型与设置”。设置窗口复用 Dreamatic 的分组标签和表单样式：

- **系统推理模型**：选择 OpenAI 或 OpenAI 兼容型，自行填写调用 URL、模型名称和 API 密钥，不预设模型列表。
- **文档分析模型 / HTML UI 页面生成模型**：默认继承推理模型的完整配置；可切换独立配置，分别填写 URL、模型、密钥和图片输入能力。
- **系统**：选择简体中文或 English，以及实时 / 演示模式。

OpenAI 模式使用 Responses API；OpenAI 兼容型使用 Chat Completions API。调用 URL 可填写 API 基础地址，也接受以 `/responses` 或 `/chat/completions` 结尾的完整调用地址，保存时会规范化。模型名称按服务商提供的信息填写。

配置保存在 `workspace/settings.json`，保存后后续任务生效，无需重启。密钥文件权限为 0600，读取配置只返回密钥是否配置，不回传密钥。旧版配置自动迁移，保留已有 URL、模型和密钥。

没有有效凭据时，模型错误会显示在对话中，已有页面不会丢失。

生产构建及本地运行：

```sh
npm run build
npm start
```

此时前后端由 http://127.0.0.1:4310 同源提供。所有项目、来源和版本保存到 `workspace/`，不提交到版本库。

## 工作流程

1. 新建项目，在输入框描述需求，上传或拖入资料，也可通过地球按钮导入网站 URL。
2. 协调智能体对齐目标；必要时在对话中询问关键问题，收到回复后继续。
3. 分析智能体基于已提取的文本、结构化数据、图片和素材来源形成证据摘要。
4. 设计智能体生成完整 HTML。旧页面和手动修改会随下一次需求传入，支持迭代。
5. 在画布中双击修改文字、拖入组件、调整样式和图层；切换桌面、平板、手机进行预览。
6. 点击“保存版本”。可恢复历史版本，或导出包含项目图片/媒体的单文件 HTML。

画布有未保存修改时会阻止切换项目和发起生成，避免覆盖手动工作。多标签页保存通过 baseVersionId 检测版本冲突；恢复历史也创建新版本。对话里的“文档分析与来源”可展开查看证据并打开原始提取结果。源代码编辑、撤销重做、图片素材选择及原生视频组件也可使用。

## 三智能体

| 角色         | 职责                                       | 输出                         |
| ------------ | ------------------------------------------ | ---------------------------- |
| Orchestrator | 意图理解、必要澄清、形成任务简报与流程调度 | 结构化 brief / 澄清问题      |
| Analyst      | 文本、图像、数据和媒体来源分析             | 带 sourceId 的证据与内容结构 |
| Designer     | UI 设计、响应式布局和页面生成              | 完整 HTML / CSS              |

角色提示词分别保存在 `.pi/agents/orchestrator.md`、`analyst.md`、`designer.md`，采用 Dreamatic 的 YAML frontmatter + Markdown 契约格式。应用负责固定的三阶段调度、类型校验、来源 ID/素材验证、一次定向输出修复、锁和持久化；Pi Agent 负责模型循环、工具调用、事件和取消。不存在额外隐式智能体。

## 文档与媒体支持

| 输入                          | 已实现处理                                                   |
| ----------------------------- | ------------------------------------------------------------ |
| PDF                           | 文字层、可识别结构/表格、可提取图片和附件                    |
| DOCX、PPTX                    | 文本、表格、内嵌图片与可识别音视频文件、图表信息             |
| XLSX、XLSM                    | 多工作表、单元格、公式及文件中缓存的结果、内嵌素材；不执行宏 |
| ODT、ODP、ODS、RTF、EPUB      | OfficeParser 支持的文本、结构与图片                          |
| CSV、TSV                      | 编码为 UTF-8 的表格、引号和不同列数处理                      |
| TXT、MD、JSON、XML、YAML、LOG | UTF-8 文本提取                                               |
| HTML                          | 静态文本提取，不运行上传的代码                               |
| PNG、JPEG、WEBP、GIF          | 保留素材，支持视觉模型时传入图片                             |
| MP4、WEBM、MP3、WAV、OGG      | 保存原始素材、供网页复用；不默认转录或理解时间轴             |
| 公开 HTTP/HTTPS URL           | 单页静态 HTML 文本、表格、图片/视频素材下载与来源记录        |

处理边界会记录在来源警告中：扫描 PDF 没有默认 OCR；旧 DOC/PPT/XLS 需先转为 DOCX/PPTX/XLSX；网站不绕过登录、不执行客户端脚本、不进行整站遍历。模型未支持视觉时不会发送图片。公式不重新计算，使用上传文件中保存的结果。

上传解析在独立 Worker 中进行，限制 384 MB V8 堆及 45 秒执行时间，超时终止且保留已完成文件。单文件上限 30 MB、每批 12 个；ZIP 解压和条目数量有限制；项目摘要保留前 180,000 字符；新导入资料的完整提取文本另存为分块文件（每来源最多 8,000,000 字符），可由工具继续读取。发给模型的单来源文本上限 25,000 字符、文本和表格单元格共用 100,000 字符预算、每来源最多 20 张表、每表 100 行和 60 列、单元格最多 2,000 字符；表格摘要最多 3,000 行，完整存储最多 100 表、合计 100,000 单元格，供工具查询。截断会明确标注，适合通过拆分材料处理大型资料。

## Skills

使用 Pi 官方 `loadSkillsFromDir` 递归发现和校验 Skill，而非另建注册引擎。所有三个智能体都获得 `list_skills` 和 `use_skill` 两个 Pi 工具，模型按需读取完整技能内容。工具会校验角色权限。新一轮运行重新发现技能，无需重新构建。

```text
.pi/skills/
  my-skill/
    SKILL.md
```

```md
---
name: my-skill
description: 何时使用这项能力
roles: [orchestrator, analyst, designer]
---

这里写方法、质量标准与输出要求。
```

默认带有意图对齐、证据分析、网页设计、数据叙事、可访问性和编辑式网页六项技能。通过 `DREAMATIC_SKILL_PATHS` 加载额外目录（macOS/Linux 用 `:` 分隔，Windows 用 `;`）。仅加载可信本地 Markdown，不执行 Skill 中的程序，也不将上传文档当作技能。metadata 可声明 roles、formats、tasks、permissions，工具支持条件发现；当前仅允许 guidance 权限。完整协议和使用示例见 [Skill 文档](docs/skills.md)。

额外解析器、OCR、转录等涉及新执行能力时，需要开发对应的受控工具；仅添加文字 Skill 不会凭空获得外部服务能力。

## 模型配置

见 `.env.example`。系统推理模型使用 `DREAMATIC_MODEL_MODE`、`DREAMATIC_BASE_URL`、`DREAMATIC_MODEL`、`DREAMATIC_API_KEY`。文档分析与页面生成可通过 `DREAMATIC_ANALYST_*`、`DREAMATIC_DESIGNER_*` 设置独立完整配置；对应 MODEL 未填写时，继承推理模型全部设置。推荐直接使用界面配置。

`DREAMATIC_AGENT_TIMEOUT_MS` 默认 600 秒（单角色所有模型轮次与工具执行的总时限），可用 `DREAMATIC_ORCHESTRATOR_TIMEOUT_MS`、`DREAMATIC_ANALYST_TIMEOUT_MS`、`DREAMATIC_DESIGNER_TIMEOUT_MS` 分别覆盖。每轮等待有效响应默认 180 秒（`DREAMATIC_AGENT_FIRST_RESPONSE_TIMEOUT_MS`）；收到文本、推理或工具参数增量后，连续无输出 90 秒才判为停滞（`DREAMATIC_AGENT_IDLE_TIMEOUT_MS`）。工具单次执行上限 120 秒（`DREAMATIC_AGENT_TOOL_TIMEOUT_MS`），期间不占用模型输出停滞计时。显式配置的旧总时限仍会生效。进度事件记录首次有效响应、工具耗时及完成状态，不记录模型推理内容或工具参数；每次角色执行最多 16 轮。停止按钮会中断正在运行的智能体；服务重启会将中断任务标记为可重试。

## 验证

```sh
npm run check
npm test
npm run build
npm run test:ui
```

核心测试覆盖文档数据保真、嵌入图片、HTML 清理/CSP、SSRF 边界、Skill 权限和递归动态发现，以及 HTTP 上传、配置保存、访问控制、重启恢复和编辑冲突；模型契约测试通过本地模拟兼容端点驱动真实 Pi Agent（工具发现、技能加载、三阶段路由、澄清停点、输出修复、来源错误、视觉编辑上下文、取消和超时）。不消耗模型费用。浏览器测试使用本机 Chrome，单独启动演示服务，验证上传、生成、编辑保存、版本和导出。

## 部署范围

这是单用户、本地优先的可运行基础版本。默认只监听回环地址；对外监听必须配置 `DREAMATIC_ACCESS_TOKEN`，在设置面板填写令牌。该令牌限制 API 访问，素材使用随机文件名 URL（并非逐项目鉴权），模型设置与密钥为该本地实例共享，适合受信任环境；多租户、独立资源授权、SSO、配额和生产任务队列尚未实现。

网页抓取会阻止私网/本机/保留地址，逐次校验重定向并将 DNS 验证结果固定到连接。生成 HTML 使用标签/属性白名单并移除脚本、事件处理器和活动嵌入；设计画布使用 iframe sandbox 与 CSP，浏览器禁止脚本执行、表单提交、外部依赖加载和跨框架访问；画布仅支持 HTML/CSS 和浏览器原生交互，复杂业务交互需要后续扩展。模型可见的用户资料由配置的模型供应商处理。

项目列表右侧“⋯”支持重命名和删除。用户设置的项目名称不会被后续生成覆盖。删除前需确认，生成或解析进行中无法操作；当前项目有未保存修改时需先保存。删除会从磁盘永久移除项目 JSON、全部版本及该项目独占素材，不进入回收目录且无法恢复。其他项目仍引用的素材会保留。项目记录默认保存在 `workspace/projects/`，素材保存在 `workspace/assets/`；可通过 `DREAMATIC_WORKSPACE` 修改保存位置。

每个项目使用独立目录，当前结构为：

```text
<workspace>/projects/<project-id>/
  project.json       # 名称、对话、来源、分析和版本元数据
  uploads/           # 上传原件，使用安全的随机文件名
  assets/            # 提取或导入的图片、音视频
  pages/             # 每个生成/编辑版本的完整 HTML
```

删除项目会永久删除该目录及全部内容，不保留共享素材。旧版扁平项目会在启动时自动迁移，素材复制到各项目独立目录并更新引用。旧版未保存的上传原件无法凭提取文本恢复；升级后的所有成功上传均保留原件。

在“模型与设置 → 系统 → Workspace 路径”填写绝对路径，保存后立即切换。原 workspace 中的数据保留，切回即可访问；此设置不会自动搬运旧目录。生成或解析期间禁止切换。系统设置文件仍保存在初始配置目录的 `settings.json`，因此重启后能找到已选择的路径。

当需求存在关键偏好缺失时，协调智能体可通过 `ask_user` 提问卡片暂停。卡片支持单选、多选和自己的答案，提交后继续分析/生成，刷新仍保留待答问题；普通输入框直接回答也兼容。协议和故障说明见 [提问交互](docs/clarification.md)。上传资料内已有的事实由分析智能体提取，不要求用户重复概括。

三个智能体已接入八项受控项目工具：`project_context_read`、`source_read`、`source_search`、`asset_inspect`、`table_query`、`page_validate`、`page_preview`、`page_patch`。工具按角色授权，资料和候选稿均限制在当前项目；分析结果可附可核对的原文或单元格定位。Designer 可预览候选稿后提交其 ID，宿主再次校验才保存版本，定向修改不会直接覆盖当前页面。

页面预览需要本机 Chrome/Chromium，可设置 `DREAMATIC_BROWSER_PATH`（或 `CHROME_PATH`）。浏览器不会自动下载，缺失时工具明确报错。预览禁用脚本、阻止外网，只载入当前项目素材。完整协议、示例、限额和旧资料兼容说明见 [智能体工具](docs/agent-tools.md)。

项目目录新增 `sources/`（完整提取内容）、`drafts/`（候选页面）和 `previews/`（截图及报告）；随整个项目一同永久删除。


## 浏览器打开与设计完成反馈

画布左上方的“打开”通过本机系统默认浏览器展示当前画布快照，包含尚未保存的可视化编辑，不自动创建页面版本。快照位于项目的 `previews/browser/`，最多保留 10 个，访问地址 1 小时有效；项目删除时一并清除。页面继续经过策略校验与 CSP 沙箱，地址不携带服务访问令牌。该功能面向本机服务：若将后端部署到远程机器，系统浏览器启动也发生在后端所在机器。

成功完成设计后，对话明确显示“设计完成”，并总结实际页面标题、主要内容、提供的资料数量和已引用的资料图片数量。演示模式会明确标识本地示例且未调用 AI。

## 文档图片筛选与复用

PDF/Office 图片提取复用既有解析器，素材保存于项目 `assets/`，记录可读取的宽高。视觉模型初始最多接收 8 张图片（单张不超过 4 MB、合计不超过 12 MB），按可用尺寸优先；`imageInputOrder` 提供图片位置与来源/素材 ID、URL 的对应。超出初始批次的图片可用现有 `asset_inspect` 工具按需查看。纯文本模型不接收图片，也不得声称看过图片。

分析器通过 `assets` 给出相关图片及布局用途，`imageDecisions` 记录使用、排除或未验证的原因。没有相关图片时明确说明限制；若推荐了图片，设计结果必须实际引用至少一张推荐图片，否则触发一次定向修复。该校验确认图片引用和项目归属，不等同于全面视觉质量审核。

编辑器提供“放弃｜保存”：放弃恢复最近保存的页面且不新增版本。允许带未保存修改切换项目，草稿在当前页面会话中按项目保留，切回可继续编辑；保存或放弃后清除草稿。刷新/关闭页面前若仍有草稿，浏览器会提示。协作记录按“智能体名称 · 操作”显示每项操作的执行者。


## 结构化结果与格式恢复

协调器和分析器优先通过 `submit_result` 直接提交角色输出对象，字段及来源证据校验通过后结束阶段。兼容旧模型的普通文本：允许识别说明文字或代码围栏中唯一完整的 JSON，拒绝多结果歧义和不完整片段，所有恢复结果仍严格验证。格式/Schema 错误只进行一次格式修复，最多 3 轮，仅开放提交工具，不再加载 Skill、搜索文档或重看图片；内容/证据错误保留一次普通定向修复。修复失败明确指出失败角色，模型长度截断单独提示。

进度区分模型输出结束与结果校验通过；事件 details 记录停止原因、输出字符数、耗时和有限的校验原因，不持久化模型原始回复、推理或工具参数。
