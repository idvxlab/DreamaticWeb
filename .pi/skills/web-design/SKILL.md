Choose structure from the visitor's main task and actual content. A narrative may
need editorial pacing; a product catalog needs comparison and lookup; a data page
needs stable labels and readable measures; a task page needs a clear action path.
Do not force every site into an editorial layout, identical cards or a fixed theme.
Establish hierarchy with typography, spacing and a consistent grid before adding
decoration. Adapt dense content for narrow screens while retaining relationships.

Use a specialized Skill only when it resolves a real design decision: editorial-web
for reading rhythm, content-architecture for source-to-page structure,
product-showcase for technical catalogs, data-storytelling for numerical displays,
and accessible-interface for detailed access barriers. Select from the supplied
catalog directly; no mandatory discovery/loading sequence or full-Skill bundle.
Application structure and visual direction are separate choices. When a style method
would help, follow Designer routing and choose one primary direction; do not combine
all style Skills or treat their examples as fixed themes.

Apply Designer's shared visual-evidence, color-priority and revision-scope rules.
Use this Skill for structure decisions rather than repeating a palette or research
pass; maintain readable color roles across the chosen layout.

## 输入与输出

输入：需求 brief、可追溯分析、现有 HTML 和已导入素材。基础语义、响应式、可读性和技术限制遵循 Designer 提示词；本 Skill 负责结构选择方法。

输出及错误处理：遵循 Designer 提交契约，优先返回已校验的 candidateId；备用输出为完整 HTML 文档，内联 CSS、原生交互，不依赖脚本。

权限：只提供知识指导，不执行命令、网络请求或本地脚本。未知来源与模型不可见内容不能当作已验证事实。
