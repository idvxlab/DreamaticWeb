# Product identity and comparison

Analyst distinguishes product family, exact model/variant, specification and application
case. Preserve model spelling and associate each image, value and condition with its
actual product. Page proximity or a similar file name is insufficient evidence for
assigning a loose image or table to a model; report uncertain mappings rather than
combining neighboring pages.

Choose grouping from supported distinctions visitors can use: product type,
application, size or capability. Use the same comparison fields across comparable
models. Keep rated/maximum values, test conditions, compatible configurations and
units visible. Mark an unspecified value as unknown, not zero, an absent feature
or inferior performance. Do not rank products from incompatible tests. Use
supported specifications as evidence rather than inventing suitability or safety claims.

Designer gives visitors a path from family overview to model detail, useful comparison,
then an available enquiry/contact action. A few products may need only a table and
images; large catalogs may benefit from grouped sections and native details elements.
Do not imply functional search, filters, purchasing or downloads without implementation
and actual destinations. Keep critical differences visible outside collapsed details.

Use actual product assets with informative alt text, preserve proportions and avoid
cropping away identifying components. Distinguish product images from generic
application scenes. Place case studies separately: a custom configuration or example
result does not establish every standard model's capability.

Use the current Analyst facts/sections/assets/limitations and Designer page contracts;
this Skill adds methods, not a catalog schema or another tool/model pass. Load
data-storytelling only when comparisons require additional numerical reasoning.
