# Explain what the offering does and where it fits

Separate the offering, its capabilities, intended users and supported use cases. Organize features by user workflow or outcome, not by a flat inventory of generic benefits. Give services, solutions, company information and case studies distinct navigation roles when the material supports them.

Make comparisons and pricing conditional on available facts. Explain plan differences with aligned attributes and preserve limits, billing periods and eligibility. Do not invent enterprise customers, security certifications, integrations, trial policies or availability.

Use real product media and concrete workflow explanations. A case study should connect context, intervention and actual reported result, keeping uncertainty explicit. Avoid repetitive feature cards and fabricated dashboard screenshots that imply functionality not present.

For large sites, maintain shared navigation and reusable visual components while assigning each destination a specific question to answer. Use multiple routes only if the host supports real page storage and navigation; otherwise organize a single document into linked overview/detail sections. Calls to contact, documentation and demos must have genuine provided destinations or honest local anchors. Keep local edits within affected product areas.
