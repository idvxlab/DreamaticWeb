# Let the data question choose the view

Identify the decision and its supporting measures. Every headline metric needs a subject, unit, time window and meaningful comparison when supplied. Keep absolute values separate from percentages, rates and percentage-point changes. Do not invent missing baselines or silently equate non-comparable periods.

Choose aligned bars for category comparison, a chronological view for trends, a table for exact values and an explanatory note for uncertainty. Use HTML/CSS visualizations when the environment prohibits scripts or SVG. Keep a readable textual/table equivalent. Avoid decorative charts, truncated axes that mislead, unlabeled scales and falsely precise derived values.

Prioritize an overview, drivers and relevant detail rather than filling rows with equal KPI cards. Preserve source qualifications, exclusions and units close to the displayed data. Missing is not zero. Derived arithmetic must be simple and supported; otherwise present the source values without guessing.

A static report can use section anchors, disclosure and grouped tables. Do not show functional-looking date filters, drill-downs or exports unless they actually work. Wide tables need an accessible scroll region on mobile, not illegible shrinking. Local edits should preserve unchanged metrics, scales, existing components and definitions.
