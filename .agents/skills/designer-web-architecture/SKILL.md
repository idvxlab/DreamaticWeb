# Let content determine structure

Identify the visitor's primary tasks and the facts supporting them. Assign each major content group a distinct purpose: orientation, explanation, comparison, evidence, procedure or next action. Choose that group's representation from its meaning, rather than repeating a card grid.

For substantial sites, define a concise navigation hierarchy and page responsibilities before filling sections, within the same implementation pass. Separate overview from detail, connect related material and expose location through labels and active/current states. A long page is appropriate for one continuous narrative; independent visitor tasks may justify separate pages when the host can actually save and route them.

Respect the output surface. If only a single document is supported, use named sections, anchor navigation, an index and progressive disclosure; do not invent additional HTML routes or claim separate pages were created. If real multi-page output is available, share navigation, tokens and components while giving each page a distinct job.

Retain exact facts and relevant media, including distinctions and supporting detail. Use comparison tables for comparable attributes, ordered lists for procedures, timelines for dated sequences, and readable prose for explanations. Make the first screen establish purpose without hiding essential information below generic marketing filler.

When restructuring an existing site, preserve working navigation, anchors, component identities and design tokens outside the affected scope. Implement the architecture in the page itself; a written sitemap alone is not a deliverable. No additional planning or review model is required.
